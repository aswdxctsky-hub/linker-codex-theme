# 更新与启动速度

## 2026-11-08 · Windows v0.6.0

修复关机后旧锁文件中的进程号被其他程序复用，导致启动器误判已有实例并静默打开原版的问题。当前官方包 `26.1103.4239.0` 已通过真实独立资料验证。

单实例的权威改为 Windows 内核维护的命名管道，并通过随机请求回执确认存活的启动实例；进程退出或被强制结束后，通道随之释放。旧 PID 锁仅记录到诊断日志后清除，历史 mounted 状态不会用于决定当前是否已经挂载。获得独占入口后，可以确定上一启动器已不在运行，更新中断回退也不再受 PID 复用影响。

固定 `bootstrap.mjs` 只负责读取版本、验签和分发。`boot-entry.mjs`、`instance-lock.mjs` 随签名发行包更新，下一次启动自动使用新入口逻辑；救援副本保留已校验的启动代码，回退旧运行时时也不会恢复旧 PID 锁。v0.5.x 必须执行一次安装迁移；此后启动逻辑更新无需重复改快捷方式或固定加载器。签名密钥与信任协议仍保留显式迁移边界。

新增 bootstrap.log，覆盖此前没有记录的提前退出、重复激活和回退。launcher.log 记录 Windows 实际开机时间、原生版本与已有窗口，便于区分系统重启、应用重启和绕过主题的官方入口。

已验证：复用仍存活的无关进程号；上次开机残留的锁、mounted 和未完成更新状态；八次并发启动；实际强制结束测试启动器后的内核锁释放；更新中断回退；新签名包中的启动代码生效且固定加载器不变；入口被篡改时拒绝并回退。真实官方进程完成三次启动、两次进程树强制结束后的恢复、重复点击和撤回，首屏约 3.9–4.1 秒。此次没有强制重启用户整台电脑，因此整机关机重启后的任务栏实测仍待用户下一次自然重启确认，不以残留状态回归冒充整机重启实测。

发布后，使用实际旧版 v0.5.2 完成 GitHub 后台下载、下次冷启动验证启用 v0.6.0、签名与入口选择核对、启动和撤回。正式安装已完成固定入口迁移，记录到旧锁忽略与清除；当前官方版本兼容验证、签名救援副本、任务栏入口及配置保留均核验通过，正在使用的账户窗口和被复用 PID 对应的无关系统服务未受影响。完整备份保留在本机 Linker/Backups。

## 2026-11-08 · Windows v0.5.2

修复启动期间页面重新加载时，开场动画和声音突然中断、直接显示主界面的问题。v0.5.1 在首屏挂载后就记为已播放；文档重载销毁动画后，后续挂载只恢复主题背景。此前完整播放的隔离测试没有覆盖这种重载。

现在仅在完整播放、主动跳过或明确终止后记为结束。启动器在进程内保留步骤、进度及语言状态，重载后恢复当前语音与视频位置；重新加载期间用同主题遮罩覆盖主内容，等开场首帧绘制后撤下。重载可能带来短暂停顿，不会因此提前结束流程。进度不写入聊天资料或跨进程持久化。

每次挂载都有独立标识，旧文档的素材请求和回调不能结束新文档的开场。页面切换中的挂载会重试；完成、跳过或恢复原版后移除预加载遮罩，后续重载不会重播或挡住原界面。

真实官方应用的独立资料测试已复现旧版问题，并覆盖中英登录语音中断续播、白龙视频中断续播、连续重载、完整结束后重载、跳过后重载及恢复原版后重载。测试核对了音频起播偏移、视频时间和重载期间主界面遮挡；另验证过期素材失败回调不会影响新开场。

发布后，正式安装通过自身更新器从 GitHub 下载并启用 v0.5.2；签名、发行清单和当前官方版本兼容验证通过，上一版 v0.5.1 保留。语言、声音及自动更新设置保持一致，正在使用的正式账户窗口未关闭；新运行时将在下一次完整启动时载入。

## 2026-11-08 · Windows v0.5.1

## 启动顺序

| 情况 | 行为 |
| --- | --- |
| 当前组合已验证 | 立即启动并播放开场，后台查找、下载后续主题包；下一次冷启动验证启用 |
| 官方应用更新或主题包待启用 | 显示独立等待窗口，下载必要更新、验证兼容，通过后进入开场 |
| 断网或 GitHub 不可用 | 继续使用本地主题；新官方版本仍可做本机兼容验证 |
| 新主题失败，旧主题兼容 | 保留并使用旧主题，记录被拒版本 |
| 本地主题都不兼容 | 进入原版，等待新的正式适配包 |
| 启用新主题时异常退出 | 下一次启动退回已校验的上一版 |
| 已有正式应用进程 | 聚焦现有窗口，冷启动时再播放开场 |

Codex 本体仍由官方渠道更新；本项目的更新器负责主题及接入代码。

## 本机兼容验证

首次遇到新的官方包，读取应用资源中与主题相关的布局、背景、层级规则，与已验证的结构指纹比对。随后启动一个独立资料目录的官方进程，通过私有管道实际挂载开场、载入素材并撤回，核对原页面属性和样式恢复。只有两步都通过才保存兼容记录。

记录同时绑定官方版本、应用文件身份和完整主题发行清单。应用文件或主题发生变化时重测；普通启动复用记录，不再读取数百 MB 应用资源。验证成功并不证明未来所有 UI 都兼容；关键结构变化会停止挂载，仍需维护者修复并发布适配。

测试资料与正式账户隔离，结束后清理本次生成的资料目录，只保留简短结果。只结束本次创建的测试 PID，不按应用名称清理进程。验证不调用摄像头，不上传聊天、账户、本机路径或日志。

## 更新包与回退

更新器读取本仓库 `win-v<version>` 的正式 GitHub Releases。清单采用 Ed25519 签名，公钥随稳定入口安装；每个可执行文件、压缩包和素材都有 SHA-256 与大小校验。下载先进入独立版本目录，验证通过才切换 `current.json`，保留上一版。

运行时压缩包约 50 KB；素材压缩包约 25.8 MB。素材按内容散列复用，只有内容变化才重新下载。下载百分比来自已接收字节；查询和本机验证没有虚构百分比。

签名无效、内容不符、下载中断或新主题启动失败均不能覆盖已可用的主题。启动器支持取消等待并打开原版。密钥轮换与稳定入口协议升级需要单独安装，不通过普通运行时更新替换。

## 启动速度

等待窗口独立于 Codex 的渲染进程，先给出反馈。原生应用初始化与素材读取并行，首屏先传背景与图标，视频和双语音声随后传入。已验证路径不等待网络检查。

本机一次隔离冷启动实测：约 **0.40 秒**出现等待窗口，**0.72 秒**发起原生应用启动，**3.51 秒**发现主页面根节点，**3.99 秒**进入开场首屏。此时兼容缓存已存在，浏览器资料为本次新建目录。数据反映该次测试，不等同于正式账户启动耗时，也不承诺相对原版零开销；原有演出长度保持不变。

当前官方版本已完成中英完整演出、角色问候、重播、跳过和完整撤回。启动器完成真实独立资料启动、兼容缓存命中、语言保留与停用持久化；新版提取样式验证了主区域透底、输入框和菜单可读性。更新存储测试覆盖签名错误、下载中断、文件篡改、上一版保留、启动中断回退及验证取消。
