# 更新与启动速度

## 2026-11-06 · Windows 26.1029.9216.0

官方应用从 `26.1029.7803.0` 更新到 `26.1029.9216.0` 后，原来的版本保护如预期暂停了主题。当前补充新版记录，保留已确认的视觉与演出。

新版应用 SHA-256：`d9af2d0789de280e7e3b8409a4b7a2e96d6e2731ea729eb0430968301fd80708`。主页面仍为 `app://-/index.html`，私有管道可用；18 条已核对的布局背景规则保持一致。新版提取样式另做了背景、输入框、菜单及撤回验证。

## 自动兼容的范围

1. 启动时检查实际安装版本，先找随安装提供或已缓存的兼容记录。
2. 没有记录时，从本仓库 `main/integration/compatibility.json` 获取小型 JSON，限时 2.5 秒、最大 128 KB，只接受固定包家族、平台、版本、SHA-256 和运行时版本要求。
3. 对应用文件做校验；匹配才挂载。不匹配时进入原版，同一版本只提醒一次。
4. 成功记录保存在本机，已匹配版本的日常启动不依赖网络。

这是**自动获取已验证的兼容记录**。维护者仍需在实际新版验证后发布记录。若应用 DOM、启动协议或主题代码需要修改，需发布并安装新的主题运行时；本实现不会自行下载执行仓库脚本，也不会宣称可以自动修复任意应用升级。

`config.json` 的 `autoCompatibility: false` 可关闭在线查询。网络请求只读取公开记录，不上传本机路径、账户、聊天或日志。

## 减少的等待

- 一次系统查询同时取得包版本、应用进程和旧启动器信息。
- 首次完整校验约 720 MB 的应用资源；之后按路径、文件大小、修改/变更时间、文件标识和预期散列确认可复用，变化后重新校验。安装目录内主题文件仍每次完整核验。
- 首屏从约 37.04 MB 整包变为约 1.95 MB 背景和图标。先绘制连接界面，再传入当前语言及另一语言的素材；视频就绪不再阻塞首屏。
- 原生应用启动与主题素材读取重叠进行。演出流程与声音长度不做加速处理。

本机单次隔离测量：完整应用校验路径约 1.31 秒，缓存路径约 0.69 秒；旧首屏挂载调用约 0.90 秒，新调用约 0.14–0.17 秒。它们是局部步骤的数据，**不是整个应用启动时间的保证**。操作系统缓存、机器性能和原生应用初始化都会影响整体体感。

## 验证范围

新版正式可执行文件在独立资料目录中完成中英完整流程、角色问候、重播、跳过及恢复。独立安装目录完成真实启动器挂载、缓存命中、恢复后停用持久化。兼容模块覆盖错误目录、离线、未知版本、运行时要求和文件变化场景。

背景验证使用从新版提取的 CSS 和独立页面；当前版本的正式账户重启后显示仍需用户确认。旧版正式账户背景此前已经获得确认。所有测试资料、提取的应用代码与截图保持本地，不随源码提交。

## 后续发布兼容记录

在目标平台检查应用版本、SHA-256、实际 DOM、完整播放与恢复。需要改代码时提高运行时要求；仅在当前运行时确实可用时追加版本条目。不要只替换旧条目的版本号或文件散列。

发布到本仓库后，已安装本次启动器的电脑会在遇到未知版本的下次启动时查询；不需要另设计划任务或常驻更新服务。
