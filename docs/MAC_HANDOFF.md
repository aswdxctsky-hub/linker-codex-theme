# Mac 实机交接

## 目标

将仓库里已经确认的 Windows 效果接到这台 Mac 的真实 ChatGPT / Codex 应用：双语科幻开场、角色鞠躬问候、进入原生对话，以及覆盖整个窗口的透明主题背景。保留原生功能和「原版 / Original」恢复入口。

用户希望日常尽量沿用原有应用图标，不新增桌面入口。Windows 已通过替换任务栏固定项实现；**Mac 的 Dock 与应用启动不能照搬这个办法，需实机确认**。不要未经检查便改官方 `.app`、签名、Dock 数据或登录项，也不要宣称 Dock 同图标或更新兼容已实现。

Windows 主线现为 v0.5.1；Mac 在 `macos-adaptation` 分支独立接续。本轮没有在 Windows 上编写或验证 Mac 启动器，也没有改动该分支；不要将本交接文档视为 Mac 已完成适配的证据。

## 从哪里开始

1. 阅读根 README、`integration/README.md`、`integration/design.md`。
2. 确认 Mac 上实际安装的应用：名称、版本、架构、bundle identifier、可执行文件、资源位置和是否为 Electron。不要假定 `ChatGPT.app` 和 `Codex.app` 的内部结构相同。
3. 先运行两个构建脚本，打开离线预览，确认素材、字体、视频与音声可播放。此步骤只证明素材可用。
4. 在独立测试资料目录中，对真实 Mac 应用做一次可撤回的简单样式验证。验证退出后无测试进程、无调试监听残留，再处理正式账户接入。
5. 在实际 DOM 和渲染结果中确认主窗口入口、背景层、标题栏、侧栏和输入框；最后才实现正式启动与恢复。

## 已确认的设计与行为

- 瓷白 `#F5F8FB`、石墨 `#263440`、冰蓝 `#77AEC1`、雾银 `#C2CFD8`。
- 画面中文为主、小号英文为辅；两套音声在右上角切换。当前一句读完再换下一环节的语言。
- 登录阶段不出现角色；确认完成后，通过信号扩散与映像加载进入角色鞠躬问候，再渐隐进入原生应用。
- 恢复按钮位于开场右下角、跳过左侧。也可从主题菜单恢复；Windows 紧急键为 Ctrl + Alt + Shift + L。
- 正文不要通过整体 opacity 变淡。背景位于窗口底层，主内容层透底；侧栏、输入框、菜单和代码块分别控制底色。
- 不要为 Mac 接入重新设计已确认的流程、替换素材或增加模拟聊天页面。

## Windows 接入事实

2026-11-08 主线增加 `26.1103.3517.0` 实机适配、签名主题包更新、本机兼容验证及 WPF 等待窗口，详见 [UPDATES.md](UPDATES.md)。`launcher.mjs` 现导出 `startSession`，稳定入口为 `bootstrap.mjs`。Mac 可参考更新状态机，但不能直接运行 Windows 包检测、WPF 窗口或测试清理逻辑。Windows 发行标签为 `win-v<version>`，Mac 应独立命名与验证，避免两端互取更新。

2026-11-06 后续维护增加了 `26.1029.9216.0` 适配、校验缓存和分批素材传输，详见 [UPDATES.md](UPDATES.md)。复用新版运行时须同时复用 `media-delivery.mjs` 的传输协议，或一次性传完整 `media`（保持向后兼容）。`compatibility.json` 当前仅包含 Windows 记录，不可拿它放行 Mac。

- 测试通过的 Store 包：`OpenAI.Codex 26.1029.7803.0`。
- 应用 ASAR SHA-256：`77ed4ddc5b388ac8b29f5035f9c98f982b095df55aad6fa6c27bb80d763b9691`。仅用于识别 Windows 基线，不是 Mac 允许列表。
- Node 启动官方可执行文件，传入 `--remote-debugging-pipe`；父进程通过额外 stdio 管道与 Chromium 通信，未开放 TCP 调试端口。
- 仅向 `app://-/index.html` 的主页面挂载主题。这个地址也需要在 Mac 上重新确认。
- 运行时主题位于独立样式节点及 closed Shadow DOM 中；恢复时释放样式、节点、音频、事件和快捷键。退出原生应用后，运行时改动自然结束。
- `launcher.mjs` 保存语言、声音、启用状态；开场每个应用进程播放一次，页面重新加载时重挂主题。
- 用户已经确认真实账户从任务栏正常启动，且主内容层的透明背景修正已生效。

## 需要替换或核对的部分

| Windows 实现 | Mac 实机工作 |
| --- | --- |
| `Get-AppxPackage`、`WindowsApps`、`ChatGPT.exe` | 实际 `.app` 元数据、可执行文件与资源路径 |
| PowerShell / CIM 查询 | Mac 进程识别、正常退出与重复启动处理 |
| `wscript.exe`、`.vbs`、`.lnk`、AppUserModelID | Mac 原生启动与通知方式；不复制 Windows 入口处理 |
| `%LOCALAPPDATA%\Linker\CodexTheme` | 明确、独立且可恢复的用户级目录 |
| `taskkill` 测试清理 | 只清理明确属于测试的进程，不按名称杀正式应用 |
| 固定 40px 顶部保留区 | 红黄绿按钮、拖拽区、全屏和 Retina 缩放 |
| Segoe UI / Microsoft YaHei 及 Canvas 字体 | Mac 中文字体、字重、基线与姓名单行排版 |
| `shell-surfaces.css` 的模块类与 data 属性 | 用实际 Mac DOM 核对；Windows 类名不是跨版本保证 |
| Windows 版本 + ASAR 散列校验 | Mac 自己的兼容记录与升级后回退逻辑 |

`integration/pipe-client.mjs` 是可考虑复用的通信组件，但 Mac 是否接受这一启动参数、管道与目标发现方式尚未测试。不修改 Electron fuse、签名或安全设置来强行复用。

## 曾经踩过的坑

**空进程列表导致冷启动报错。** 旧 PowerShell 管道在零匹配时返回空文本，`JSON.parse('')` 报错；独立测试模式绕过了正式冷启动检查，未暴露问题。现已修复。Mac 必须分别测无进程冷启动、已有正式进程、已有主题启动器，不用独立预览代替这三种场景。

**背景只在顶部可见。** 外层 body 有图片，主面板和 `WorkspaceContent::before` 仍是实色。修正覆盖了两层底色，保留输入框和菜单的可读性。Mac 要实测进入真实对话后的效果，不能仅以 `background-image` 有值判断通过。

**外部恢复不够方便。** 用户明确希望恢复放在开场里，且不增加日常快捷方式。这个要求继续有效。恢复后需确认再次从日常入口打开也不会重新启用主题。

## 完成判据

- 独立预览与真实应用挂载分别验证；两者不要混称。
- 正式账户下播放中英开场、跳过、重播、切换音声、角色问候均正常。
- 透明背景贯穿实际聊天窗口；侧栏、输入框、菜单、代码可读，原有交互正常。
- 正常关闭、重新打开、已有进程时启动、全屏/缩放不会破坏入口或重复播放。
- 点击「原版」立即恢复界面并保持停用；退出、重开后仍为原版。
- 更新或不兼容时可进入官方原版，不让主题故障阻断工作。
- 原生包、账户、聊天和项目不因适配被替换或清空。

这些是后续验收目标，当前不能标为 Mac 已通过。
